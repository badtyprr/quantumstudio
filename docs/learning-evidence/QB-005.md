The ideal inverse Fourier transform gives uniform zero-input probabilities, 1/8 each. The generated program uses rounded decimal angles, so its literal probabilities need not equal 1/8 exactly; that complete execution has **not** passed.

## Exact-execution investigation, 2026-10-24

The published `5b982f1f` worker still exceeded a three-second diagnostic limit on the full imported program. Timers in a separate diagnostic build located the dominant cost in symbolic gate application: a 15-gate prefix spent approximately 2.71 seconds executing, 0.12 seconds calculating output weights, and 0.02 seconds formatting. The full program timed out during gate application at 12 seconds. Disabling expression expansion was rejected: the same prefix took about 7.45 seconds and produced 90 KB of output. These timings identify an implementation area, not a completed fix or a portable CI threshold.

A separate Python feasibility experiment represented each amplitude as an exact integer-coefficient sum of rational-angle phases, with explicit powers of two and square roots of two for normalization. It consumed the current frozen importer's gate expressions without rounding their angles to pi. All 55 unitary gates completed in about 0.94 seconds, producing 28,167 amplitude terms. Expanding all eight squared amplitudes took about 35 seconds overall and produced 22,815–22,989 terms per outcome. Their sum cancelled algebraically to exactly one.

An independently implemented dense-matrix calculation using mpmath 1.3.0 at 60 decimal digits agreed with each saved probability polynomial to better than `1e-50`. The largest deviation from ideal 1/8 was approximately `7.38e-17`. For example, computational-basis state `001` had probability approximately `0.1250000000000000737654995020481499`; the source's measurement destinations and selected classical-bit order map it to output label `100`. These checks cover the imported literal gate expressions from zero input. They do not claim that the shipped exact executor completed, that arbitrary circuits are supported by the experiment, or that the GUI can handle these expanded results.

Next implementation work must address both execution and result size. A compact exact representation needs explicit operation/term budgets, cancellation, supported-domain checks, and a safe route for circuits outside its domain. Test it through the same execution interface used by the worker, including the full unchanged source, before closing this performance gap. Do not substitute a numerical-only result or an idealized Fourier circuit.

# QB-006: qBraid phase-estimation notebook

Partial source audit, 2026-10-20. The intended notebook result has not passed unchanged.

Source: [qpe.ipynb at 86787e1](https://github.com/qBraid/qbraid-lab-demo/blob/86787e1ba372facc224f925189755e69c479828b/qBraid-Algorithms/qpe.ipynb), with `unitary.qasm` and `prepare_state.qasm` from the same directory and revision. The input files define a Z operation and an X eigenstate preparation, respectively. The lesson expects phase 1/2, represented as `100` with three counting qubits.

## Local execution and discrepancy

Unchanged cells 2, 4, 6, 8, 10 and 22 executed in an external environment with qbraid 0.13.0, qbraid-algorithms 0.1.3 and PyQASM 1.3.0. Dependency installation was preprovided and shell file display was adapted to file checks. No provider, submission, result retrieval or histogram cell ran. This does not implement notebook execution inside QuantumStudio.

The generated three-counting-qubit QASM imported through the frozen compiler in published QuantumStudio revision `7c66ed79d14f1677f4bcbd11f0e87335c209e268`. Numerical sampling with 10,000 shots and seed 1731 returned `000` every time. This contradicts the lesson's intended prepared-state example, but is consistent with the actual generated QASM: the `psi` qubit remains in zero because there is no preparation operation.

Inspection of the installed generator confirmed the omission. Its `_get_psi` helper returns the preparation **gate definition**, renamed `prep_eigenstate`. The QPE template inserts that definition before `qpe(q, psi)` but never calls `prep_eigenstate`. After unrolling, the definition disappears without an X operation on `psi`.

A separate diagnostic copy inserted `x psi[0];` immediately before the first Hadamard. The same frozen import and sampling route then returned `100` in all 10,000 shots. Original pinned inputs and original generated output were preserved. This adaptation supports the diagnosis; it does not establish unchanged-notebook coverage or exact probability evaluation.

## Development decisions and remaining acceptance

- Track the preparation omission as an external qbraid-algorithms 0.1.3 generation issue. Do not add a QuantumStudio importer rule that invents a missing preparation operation.
- If a supported generator version or documented notebook correction becomes available, rerun the unchanged local cells and verify the intended phase result and bit ordering. Keep the original failure evidence.
- Verify generated subroutine include import, editor save/reopen/export, and the default-size program separately. Successful generation does not prove those routes work.
- Exact execution and complete numerical distribution verification remain untested for this fixture; the evidence here is seeded sampling.
- DEV-13/15 still cover in-app Python/SDK and external provider execution. QB-006 stays unchecked.

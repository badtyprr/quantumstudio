## Normative rules and derived runtime requirements

[Subroutine specification](https://openqasm.com/language/subroutines.html): scalar classical arguments are values; quantum arguments reference caller qubits and must not overlap. Array formals require readonly/mutable and are references, with explicit shape or fixed rank. Multiple overlapping mutable references are forbidden. Reference lifetime ends with the call while underlying array storage persists. `sizeof(view,axis)` gives the selected dimension, default axis zero; rank-only formals return a runtime uint. The specification does not give a blanket ban on overlapping readonly views, so do not reject them merely because their backing array is shared.

Engineering consequences: evaluate scalar actuals in caller context, convert to declared type once, then store independent slots; copy/convert a return before destroying locals. Snapshot resolved quantum identities and selected array view metadata at call entry. Later mutation of an index variable cannot retarget a formal. Element writes through mutable views affect the caller immediately; readonly access cannot be regained as mutable by nested forwarding. Compare physical element identities for overlapping mutable slices, not just names/bounding intervals. Resolve/validate every actual, including unused parameters, before the body runs. Detect missing returns even when a typed result is discarded. Preserve established short-circuit call behavior.

[Types and arrays](https://openqasm.com/language/types.html#arrays): arrays have constant immutable shape, at most seven axes, global declarations, and undefined uninitialized elements. Negative array indices count from the end; -n is the first element. Scalar element types include int/uint/float/angle/bool (also complex/duration in the language); bit and qubit are not array element types. Array copies/slice assignments preserve matching shape/type; zero-sized axes are legal but have no valid element. Unlike quantum registers, classical array concatenation copies values. These rules must not inherit DEV-07's optional nonnegative quantum-index subset.

Engineering consequences: retain per-element definedness; normalize each negative axis before bounds checks; validate all axes even when another dimension/index is unresolved; protect shape products before allocation. For overlapping copy assignment, capture RHS values before writes so results do not depend on traversal direction. Preserve nested initializer shape, not merely flattened element count. Reject fractional indices, shape mismatches, writes through readonly views, and out-of-bounds accesses with source locations. Deferred/unexecuted branches must not read invalid elements. Zero-size arrays may be passed to unused formals or iterated zero times without inventing an element.

[Scope rules](https://openqasm.com/language/scope.html) give declaration-to-scope-exit lifetime and forbid arbitrary mutable-global capture inside functions. Array globals must be passed as references, not made magically visible to callees. Fresh locals must not retain prior activation values. Cleanup must run for normal exit, return, break and continue; clearing a view must not clear caller array storage. Preserve lexical constants and caller-shadowing rules when evaluating formal type sizes.

[For-loop rules](https://openqasm.com/language/classical.html#for-loops) permit scalar discrete collections, inclusive integer ranges, bit registers and one-dimensional arrays/slices. Iteration follows sequential index order; assigning the loop variable does not modify the source array or change the next assigned iteration value. Treat a discrete collection as an ordered list, not a mathematical deduplicated set. The spec text does not unambiguously settle mutation of a future source-array element while iterating it. Document the chosen evaluation model and test it; do not claim a source guarantee for whole-array snapshot versus live future reads. Recommended value model: evaluate the iterable expression once at loop entry to a bounded value sequence, then assign an independent typed loop slot on each iteration. This is a product choice pending stronger primary evidence.

## Required authored runtime and mutation tests

- Feed measurement into float/angle actuals and array elements; compute an index from measurement, write/read that element and feed the value to a gate. Test int/uint/bool, float32/64 and angle arrays using their existing typed semantics.
- Call a float32-return routine repeatedly in a runtime loop; mutate a formal without changing its caller scalar, return through nested branches, and test a missing-return path after a previous successful call. Early exit must neither reuse old results nor run later effects. Add angle-return wrap/width-conversion and nested-call controls.
- Mutable sliced view writes aa[3] through aa[1:3][2]; caller sees it. Nested forwarding retains permissions and caller mutation. Two readonly overlapping views work; overlapping mutable views reject before body effects. A disjoint strided pair sharing one backing array is not overlap. Cover readonly+mutable overlap separately and document policy: the cited text explicitly prohibits multiple overlapping mutable references, not every mixed pair.
- Snapshot dynamic slice bounds, quantum actuals and scalar argument values at entry; later selector mutation cannot change their identity. Include actual argument expressions that call functions, unused formals and short-circuited calls so evaluation order and validation cannot disappear during lowering.
- Array indices -1 and -n succeed; -n-1,n,fractional,undefined fail. Test each axis, malformed nested initializer, zero-length shape, rank mismatch, correct-element-count/wrong-shape mismatch, overlapping slice assignment and independent per-element definedness.
- Iterate runtime scalar collections with duplicates, array slices, float/angle arrays and bit registers; retain order, independent loop slot and restoration after shadowing. Exercise nested break/continue/early return, empty collection and collection expressions containing calls. Freeze and test the selected source-array-mutation model explicitly.

Independent reference: small typed-store interpreter with explicit arrays/views and direct gate matrices, separate from importer/unroller output. Compare exact branches for measurement-dependent cases and sampled frequencies; observe final storage for writes/returns, since a circuit-only oracle can miss discarded values. Canonical serialization must retain typed values, view mapping, permissions, shapes and lifetime operations, not host-language pointers.

## Limits and completion evidence

Retain the existing 65,536-element cumulative storage ceiling (or explicitly revise it), checked with overflow-safe products before allocation; rank1..7, bounded scalar widths inherited from existing numeric support, call depth32/calls4096/expanded AST65536 and expression limits should compose rather than reset per view/call. Count view descriptors/expanded selections and iteration work too; a slice must not bypass the backing-storage budget. Resource failures must be source-local, bounded and cancellable.

Finite product limits are necessary, but unsupported functionality cannot be hidden as a limit: omitting mutable references, runtime collection iteration, multidimensional references or floating/angle returns leaves a requested DEV-08 category unfinished. Complex/duration arrays and unsupported widths may remain explicit type boundaries inherited from the numeric engine, provided documentation states them and rejection tests cover them; do not claim every OpenQASM array type.

## Reproduce the include gap

Generate `oracle.qasm` using `bv.generate_oracle("111")` in the external
environment, then import this program with the dependency beside it:

```qasm
OPENQASM 3.0;
include "oracle.qasm";
qubit[3] q;
qubit[1] ancilla;
oracle(q, ancilla);
```

Expected: three controlled-X operations from data wires 0, 1 and 2 to ancilla
wire 3. Actual: importer exits with an error restricting includes to
`stdgates.inc` and `qelib1.inc`. Explicitly inlining the generated declaration
imports those three operations successfully.

Similarly, `bv.save_to_qasm("011")` generates `bernvaz.qasm`. Calling
`bernvaz(q, ancilla)` through an include fails; inlining imports ten operations.
These probes establish an include-resolution gap, not a general failure of
subroutine-local values or compile-time wire indices.

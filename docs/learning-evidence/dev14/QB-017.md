## Original semantic rejection

The retained original QASM contains `bit[2] b`, `qubit[2] q`, H and CNOT, with no
measurement. The actual QIR declares two qubits and **two allocated results**,
then calls `result_record_output` for results 0 and 1 without a preceding `mz`.
The preliminary zero-allocation hypothesis was not reproduced; the unmeasured
result problem was reproduced. LLVM verification accepts the original module
and fresh text/bitcode parses, because those checks do not establish measurement
semantics. Both original exports retain their original bytes.

The witness records `unmeasured_result` for each output and
`original_runtime.state = not_run_invalid_result_accounting`. It does not run
this invalid observation sequence, inject measurements, change `record_output`,
or accept hypothetical default zeros as Bell counts. The run retains
`original_execution = succeeded`, `authored_verification = failed` and
`SEMANTIC_ACCEPTANCE_FAILED`. This finding belongs to the pinned external
conversion path; it is not a native calculator mathematics defect.

## Separately authored local QIR controls

The witness copies the original Bell circuit and adds measurements in a separate
object. Its premeasurement QIR operations must match the original H/CNOT sequence.
Two additional authored circuits prepare logical `(q0,q1)=10` and `01` using X
gates. Before execution, the finite inspector checks measurement/result mapping,
output slot order, known instructions and result allocation. It rejects other
shapes; it is not a general QIR verifier or production QIR parser.

qirrunner executes both textual IR and bitcode locally at seed 1731. Raw output
streams and their hashes are retained. A strict shot/result parser requires two
Boolean outputs and a successful end record per shot. Logical order is q0 then
q1, explicitly checked against measurement/result/output slots.

| Authored control | Independent expected counts | Observed text and bitcode |
| --- | --- | --- |
| Measured Bell, 4096 shots | Only 00/11, probability 1/2 each, tolerance 0.05 | 00:2046, 11:2050 |
| q0=1, q1=0, 256 shots | 10:256 | 10:256 |
| q0=0, q1=1, 256 shots | 01:256 | 01:256 |

These are counts, not observed amplitudes. No amplitude-return API is claimed.
Text and bitcode give identical counts at the fixed seed. Authored malformed IR
produces a parse error; an unsupported QIS name and an out-of-range result
allocation are rejected before runtime, even where LLVM verification succeeds.
